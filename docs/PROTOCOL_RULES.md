# 프로토콜·도메인 핵심 규칙 (구현 시 절대 준수)

> 원천: `EMS-RTDS_시뮬매니저_Modbus_프로토콜맵_v1.1.xlsx`, 시퀀스 설계서 v1.7 §8.
> 이 규칙과 관련된 코드를 추가·수정하면 **이 파일의 해당 절도 함께 갱신**한다.

## 1. 레지스터 표기

- 동일 참조주소가 링크마다 다른 의미를 가진다 → 항상 시트 번호 원문자 접두 사용:
  - **①** EMS–매니저 링크 (매니저=Server, EMS=Client) — 예: ①HR 400007 = 시나리오 ID
  - **②** RTDS–EMS 링크 (RTDS=Server, EMS=Client) — 예: ②HR 400001 = 유효전력 P 지령
  - **③** 매니저–RTDS 링크 (매니저=Server, RTDS=Client) — 예: ③IR 300011 = 초기 SOC 값
- 참조주소는 0-base 6자리: Coil 0xxxxx / DI 1xxxxx / IR 3xxxxx / HR 4xxxxx
- 객체는 Server가 보유. Client는 Coil·HR에 쓰고, DI·IR은 읽기전용.
- **링크① EMS→매니저 DI/IR 기록은 미러 HR(FC16) 경유** (프로토콜맵 v1.1 시트1·설계서 v1.6 §8 확정):
  DI n ↔ HR (10000+n) 참조 410000대 / IR n ↔ HR (30000+n) 참조 430000대 (`protocol/mirror.py`).
  한 FC16 요청은 한 미러 영역 안에 완전히 포함될 것(경계 걸침·범위 초과는 무시). 읽기는 원 주소.
  오프셋은 기본값 — EMS측 합의로 확정([OPEN_ISSUES #2](OPEN_ISSUES.md)).
- 코드의 레지스터 정의는 `backend/app/protocol/` **한 곳(SSOT)** 에만 둔다. 매니저 서버·에뮬레이터·테스트 전부 이를 import. 주소·스케일 하드코딩 금지.

## 2. 스케일·부호

- **부호: 방전(PCS→계통) +, 충전 −** — 전 링크 공통.
- 스케일은 **링크마다 다르다**. 변환표는 protocol 상수로 고정:

| 항목 | 스케일 | 예 |
|---|---|---|
| 링크② 전력·전압·전류 | ×100 | ②HR 400001 P지령 ±250.00 kW |
| 링크③ Historian 전력 | ×10 | ③HR 400002 ESS 전력 ±3276.7 kW |
| 요약 SOC | ×100 | ②IR 300005, ③HR 400003 (0~100%) |
| Bank SOC/SOH | ×10 | ②IR 300021/300022 (0.1% 분해능) |
| 역률 | ×1000 | −1.000~1.000 |
| 주파수 | ×100 | 예 60.00 Hz |
| DC링크/Bank 전압 | ×50 | ②IR 300020/300023 |
| Bank 전류 | ×50 | ②IR 300024 |
| 외기온도 | 링크① ×10 / 링크③ ×100 | 같은 물리량도 링크별 상이 — 주의 |
| 적설량 | 링크① ×10 / 링크③ ×100 | 〃 |

- 바이트 순서 big-endian. 32-bit 값(누적 전력량 ②IR 300033~300036)은 상위워드 우선, 하위워드 ×10 kWh.

## 3. 원자성·핸드셰이크

- **CMD Seq(②HR 400011) / RES Seq(②IR 300000)**: 데이터 블록 기록 완료 후 **마지막에** +1. 수신측은 Seq 변화 시에만 블록 일괄 래치(원자성).
- **구간 경계 원자성**: 매니저는 구간 인덱스(①HR 400006)를 갱신하기 **전에** 해당 구간의 시각·기상 레지스터를 먼저 갱신 (EMS가 인덱스 변화를 트리거로 읽을 때 정합 보장).
- **초기 SOC 주입(P2) 레벨 핸드셰이크**: ③IR 300011 세트 → ③DI 100000 트리거=1 → RTDS 주입 → ③Coil 000001 ack=1 → 매니저 트리거 해제 → RTDS ack 해제. 트리거는 **최초 기동에만** 세운다(재접속 시 생략, §3.8 R-2).
- **지령-echo 검증**: EMS 기록값 vs ②IR 300031/300032 적용값 대조, 불일치 3회 지속 시 알람·재기록(CMD Seq +1).
- **예측 블록(B-4)은 [1구간]만 전달** (설계서 v1.7): ①IR 300002(기준 구간) + 300003~300006([1구간]
  PV·부하·스케줄·목표SOC)만 유효 기록 — [2~4구간] 300007~300018은 예약(0 기록).
  예측-실적 페어링(B-9)·예측률 평가(§7.3)는 선행 h=1 단일 기준. EMS 내부 예측 지평은 자유.

## 4. 가상시계 자유진행 (free-running) 원칙

- 가상시계는 Run 시작(P3)~종료(P5)까지 **어떤 노드의 접속 여부·상태와 무관하게 계속 흐른다**. 매니저는 노드를 기다리거나 시계를 멈추지 않는다.
- ①Coil 000002 '일시정지'는 **운영자의 명시적 조작에 한해서만** 시계 정지(자동 예외처리로 사용 금지).
- 노드는 언제든 접속(Late-join/Rejoin, 설계서 §3.8)해 그 시점 가상시각 기준으로 합류. 미접속 구간의 지령 공백은 소급하지 않으며 결과 그대로 Historian에 남긴다.
- 환산: 가상 1분 = 실 (가속배율/15) 초. 배율 10 s → 실 0.67 s 폴링. 링크별 독립 TCP 세션 병행(직렬화 금지).

## 5. 연결중개 (P1 — 매니저 고유 역할)

RTDS가 ③Coil 000000 'RTDS 운전중'=1 기록 → 매니저 감지 → ①Coil 000004 'RTDS 준비됨'=1 세트 → EMS가 읽고 RTDS(Server)에 직접 접속. RTDS 단절 시 매니저가 ①Coil 000004=0으로 복귀.

## 6. 생존감시·예외 (설계서 §6)

- Heartbeat: EMS ①IR 300000 / RTDS ③HR 400000 — 실 1 s 증가, **3 s(또는 폴링 3배) 미갱신 시 단절 판정**.
- EMS 단절 → ③IR 300003 'EMS 상태'=0 + Historian 단절 이벤트 (시계는 계속. RTDS는 워치독 정체로 자체 P=0).
- RTDS 단절 → ①Coil 000004=0 → EMS 지령 중단·계측 결손 표시. 매니저는 결손 구간 마킹.
- 워치독: EMS가 ②HR 400010을 가상 1분마다 +1. RTDS는 3주기 정체 시 PCS 안전상태(P=0) 천이.
- PCS 고장: 경알람 → 고장 리셋(②Coil 000005) 1회 시도 / 중알람(과온·지락) → E-Stop(②Coil 000002).
- 타이밍: 응답 타임아웃 1,000 ms / 재시도 3회 / 재접속 1~5 s.
- **Run 무효**: 단절 누적 허용 한도(총 구간의 0.5% = 14구간) 초과, echo 불일치 지속, 고장 시 해당 Run 재수행.

## 7. Run A/B 공정 비교 조건

- 두 Run 동일: 시작시각·기간(가상 30일)·가속배율·초기 SOC 50%·SOC 상하한 90/10%·충방전 제한 250 kW·기상/부하 시나리오.
- 차이는 **시나리오 ID**(①HR 400007: A=1, B=2)와 **제어모드**(②HR 400000: A=2 경제, B=3 피크저감)뿐.
- Run B 시작 시 보존 SOC가 아닌 **초기 SOC 50% 재주입**.
- P6 케이스 전환: 리셋(①Coil 000003, ③DI 100002) → 시계 되감기 → 시나리오 포인터 리셋 → 시나리오 ID=2. EMS 예측 이력 버퍼 초기화(사전 학습 모델 파라미터는 유지).
- 부하 실측은 ③IR 300008로 **RTDS에만** 전달 — EMS는 블라인드(자체 예측), 예측 오차가 자연히 성능에 반영.
- 웜업: Run 시작 후 초기 1일(96구간)은 예측률 통계에서 '웜업'으로 구분 집계(제외 아님), 양 Run 동일 적용.
