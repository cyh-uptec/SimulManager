# EMS 시험 매뉴얼 — EMS 시험 페이지 사용법

> 대상: EMS 담당자·시험 운영자.
> 목적: **RTDS 없이 EMS만** 시뮬매니저에 접속시켜 링크① 프로토콜과 P0~P6 시퀀스를
> **실운영과 동일한 파이프라인**으로 검증한다. RTDS 몫의 동작은 페이지의 **가상 RTDS**가
> 자동 재현하므로, EMS 입장에서는 실제 3노드 환경과 똑같이 시험이 진행된다.

---

## 1. 시험 준비 (사전 조건)

| 항목 | 내용 |
|---|---|
| 접속 대상 | 시뮬매니저 `<서버 IP>:7000` — Modbus TCP (시험 모드 per_link_port, 링크①) |
| 포트 변경 | 웹 UI ⚙ 설정 → 네트워크 (변경 시 서버 즉시 재기동, EMS 재접속 필요) |
| 방화벽 | 매니저 PC 인바운드 TCP 7000 허용 |
| 웹 UI | 아무 PC 브라우저에서 `http://<서버 IP>:8100` → 좌측 메뉴 **EMS 시험** |
| 시나리오 데이터 | **데이터 메뉴에서 부하·기상 CSV 업로드** — 없으면 Run 시작이 거부됨 |

**EMS 구현 전제 (링크① 규약 요약)** — 상세: [PROTOCOL_RULES.md](PROTOCOL_RULES.md)

- 인코딩: big-endian, INT16은 2의 보수. Unit ID는 무관(서버가 모두 응답).
- EMS는 Client이므로 DI/IR에 직접 쓸 수 없음 → **미러 HR에 FC16으로 기록**:
  - DI n → HR (10000+n), 참조 410000대 (예: EMS 준비완료 → HR 410000)
  - IR n → HR (30000+n), 참조 430000대 (예: EMS Heartbeat → HR 430000)
  - **한 번의 FC16은 한 미러 영역(DI대 또는 IR대) 안에만** — 경계 걸침·범위 초과는 매핑되지 않음
- 스케일: 외기온도·적설량 **×10** (링크③은 ×100 — 혼동 주의), 예측 블록 **×100**,
  ESS 스케줄 부호 **방전 +, 충전 −**
- 예측 블록은 **[1구간]만 전달** (IR 300003~300006). [2~4구간]은 예약, 0 기록 (설계서 v1.7)

## 2. 화면 구성 — 항목별 설명 (위에서 아래 순서)

### 2.1 상단 헤더
현재 시퀀스 단계(P0 대기 ~ P6), 가상시각·구간 인덱스, **접속 안내**(EMS가 붙을 포트)를 표시.

### 2.2 실장비 접속 상태 카드
EMS가 실제로 붙었는지를 **3단계로 구분**해 보여준다. 연동 디버깅의 출발점.

| 단계 | 의미 | 정상 표시 |
|---|---|---|
| ① TCP 접속 | 세션이 열려 있는지 + 접속 수·상대 주소 | 접속됨 (1) — `<EMS IP>:<포트>` |
| ② Modbus 폴링 | 실제 요청(읽기 포함)이 오는지 — 마지막 요청 경과 초 | 수신 중 — 0.x s 전 |
| ③ Heartbeat 판정 | 규약 준수 여부 (실 1 s 증가, 3 s 미변화 시 단절) | 정상 · HB 증가 중 |

상단 배지: **● 접속 · 폴링 중** → 정상 / **접속됨 · 폴링 없음** → TCP만 열림(아래 §7 참조) /
**미접속** → 세션 없음. 가상 노드의 기록은 ①②에 포함되지 않으므로 실장비 신호만 반영된다.

### 2.3 가상 RTDS 카드
켜면 매니저가 **정상 RTDS의 프로토콜 행동을 자동 재현**한다:
③Coil0 운전중 세트 → 연결중개로 ①'RTDS 준비됨'=1 · Heartbeat 실 1 s ·
초기 SOC 핸드셰이크 ack 응답 · 가상 1분마다 간이 계측(③HR) 기록.
**EMS 단독 시험에서는 켜 두는 것이 기본**이다 — 그래야 Run이 실운영과 동일하게 자동 진행된다.

### 2.4 트리거 제어 (수동 오버라이드) — EMS가 읽는 지령 (①Coil)
정상 흐름은 "가상 RTDS ON + Run 시작"으로 자동 진행되므로, **특정 신호만 강제하고 싶을 때만** 사용.

| 토글 | 참조 | 설명 |
|---|---|---|
| RTDS 준비됨 | ①Coil 000004 | ★연결중개 — 원래 RTDS 접속 시 자동 세트. 수동 세트 시 EMS는 링크② 접속 단계로 진행 |
| 운전 시작 | ①Coil 000000 | P3 개시 신호 — EMS 제어 루프 시작 |
| EMS Enable | ①Coil 000005 | EMS 연산 활성 — 운전 시작과 함께 세트되어야 지령 산출 |
| 운전 정지 | ①Coil 000001 | P5 종료 — EMS는 지령 중단·안전 상태로 |
| 일시정지 | ①Coil 000002 | 운영자 조작 전용 |
| 리셋 | ①Coil 000003 | P6 — EMS 내부 상태 초기화 |

**주의**: Run 진행 중에는 시퀀스 엔진이 같은 Coil을 덮어쓸 수 있다 — 수동 강제는 대기(P0) 또는
단계별 검증 시에 사용할 것.

### 2.5 EMS 모니터링 — EMS가 기록한 값 (①DI·IR, 미러 HR 경유)
EMS가 미러 HR에 쓴 값이 **DI/IR에 매핑되어 표시**된다. 여기 값이 바뀌면 미러 매핑이 정상.

- 상태 비트: EMS 준비완료 / 연산중 / 예측 완료 / 알람 (DI 0~3 ← HR 410000~410003)
- 생존·상태: EMS Heartbeat (IR 300000 ← HR 430000), 상태코드 0정상/1주의/2고장
- 예측 블록 [1구간] (IR 300002~300006 ← HR 430002~430006):
  예측 기준 구간 · PV 예측(×100 kW) · 부하 예측(×100 kW) · ESS 스케줄(×100 kW, +방전/−충전) · 목표 SOC(×100 %)

### 2.6 매니저 배포값 — EMS가 읽는 시각·기상 (①HR)
Run 중 가상 1분마다 갱신된다. EMS가 읽어야 할 값과 스케일:

| 항목 | 참조 | 스케일·단위 |
|---|---|---|
| SIM 가상시각 (년/월/일/시/분) | ①HR 400000~400004 | ×1 |
| 시간 가속 배율 | ①HR 400005 | ×1 s (실 15분 → 이 초) |
| 구간 인덱스 | ①HR 400006 | 0~95 — **시각·기상 갱신 후 마지막에 갱신됨** |
| 시나리오 ID | ①HR 400007 | 1=Run A 규칙기반 / 2=Run B 최적 |
| 일사량 | ①HR 400008 | ×1 MJ/m² |
| 외기온도 | ①HR 400009 | **×10** ℃ (INT16) |
| 적설량 | ①HR 400010 | **×10** cm |
| 기상 상태코드 | ①HR 400011 | 0정상/1폭염/2폭설 |

> EMS 읽기 권장: **구간 인덱스 변화를 감지한 뒤** 시각·기상 블록을 읽으면 원자성이 보장된다
> (매니저는 시각·기상을 먼저 쓰고 인덱스를 마지막에 갱신).

### 2.7 Hex 모니터 — 링크① 전체 레지스터
모든 레지스터의 참조주소·이름·물리값·Raw·Hex를 1초 주기로 표시, **변화 시 하이라이트**.
EMS가 보낸 원시값이 스케일·부호 처리 전에 어떻게 도착했는지 검증할 때 사용
(예: 온도 25.3℃ → Raw 253, ESS −50.00 kW → Raw 0xEC78).

## 3. 표준 시험 순서 (전체 시퀀스 — 권장)

**0단계. 준비**: 데이터 메뉴에서 부하·기상 CSV 업로드 확인 → EMS 시험 페이지 열기.

**1단계. 접속 확인** — EMS를 `<서버 IP>:7000`에 접속시키고 폴링 시작.
- 카드가 차례로 바뀌는지 확인: 미접속 → 접속됨·폴링 없음(연결만 된 상태) → **● 접속 · 폴링 중**

**2단계. Heartbeat 확인** — EMS가 HR 430000에 실 1 s 주기로 증가값 기록 (FC16).
- ③Heartbeat 판정이 **정상**으로, Home의 EMS 배지도 **정상**으로 바뀜
- EMS 준비완료(HR 410000=1)도 세트 → 모니터링 '상태 비트'에 표시

**3단계. 가상 RTDS ON** — 카드 토글 켜기.
- 잠시 후 트리거 제어의 'RTDS 준비됨'이 자동 1로 (연결중개 동작 = EMS는 이 비트를 보고 진행)

**4단계. Run 시작** — Home 화면에서 시나리오 선택(Run A/B) → **▶ Run 시작**.
- 자동 진행: P2 초기화(시나리오 ID·가속배율 배포, 초기 SOC 핸드셰이크는 가상 RTDS가 ack)
  → P3 개시(①'운전 시작'=1, 'EMS Enable'=1) → P4 운전 루프
- EMS 확인 사항: ①Coil 지령 인지 → ①HR 시각·기상이 가상 1분마다 갱신되는지 → 15분(1구간)마다
  예측 블록 기록

**5단계. EMS 기록 검증** — 모니터링·Hex 모니터에서:
- 예측 완료 비트(HR 410002)와 예측 블록 값이 구간마다 갱신되는지
- 스케일 확인: 화면 물리값이 EMS가 의도한 값과 일치하는지 (다르면 스케일 착오 — Hex로 Raw 대조)
- 시퀀스 메뉴에서 P1~P4 이벤트가 순서대로 기록됐는지

**6단계. 종료** — Home ⏹ 정지 (P5) 또는 ⏮ 리셋 (P6 케이스 전환) → EMS가 '운전 정지'/'리셋'
비트에 반응하는지 확인.

## 4. 개별 신호 시험 (수동 오버라이드)

Run 없이 특정 반응만 확인할 때: 대기(P0) 상태에서 트리거 제어의 토글을 직접 조작한다.
예) 'RTDS 준비됨'만 1로 → EMS가 링크② 접속 단계로 넘어가는지 /
'운전 정지' 1로 → EMS가 지령을 멈추고 안전 상태로 가는지.

## 5. 예외(단절) 시험

| 시험 | 방법 | 기대 동작 |
|---|---|---|
| EMS 단절 판정 | EMS의 HB 기록 중단 (폴링은 유지해도 됨) | 3 s 후 판정 '단절', 시퀀스 로그에 EMS 단절 기록, ③'EMS 상태'=0 (가상시계는 계속 진행 — 자유진행 원칙) |
| 재접속 (Late-join) | HB 재개 | 판정 '정상' 복귀, 현재 환경 즉시 제공, SOC 트리거는 재세트되지 않음 |
| 단절 누적 | Run 중 단절 반복 | Home '단절 누적' 증가 — **14구간 초과 시 Run 무효** |

## 6. 시험 vs 실운영 차이

없음 — 시험 페이지는 실운영과 **동일한 엔진·시퀀스·Modbus 서버**를 사용한다.
차이는 (1) RTDS 몫을 가상 RTDS가 대신한다는 것, (2) 포트 구성(시험 ①7000/③5021,
운영 single 502 + IP 라우팅)뿐이다. EMS는 링크②(RTDS 직결) 부재만 감안하면 된다.

## 7. 문제 해결 (FAQ)

| 증상 | 원인·조치 |
|---|---|
| 미접속 | TCP 자체가 안 열림 — IP·포트(7000), 방화벽, 케이블/네트워크 확인 |
| 접속됨 · 폴링 없음 | TCP만 열리고 Modbus 요청이 없음 — EMS에서 **읽기(폴링)를 시작**했는지, 프로토콜이 **Modbus TCP**(RTU over TCP 아님)인지 확인 |
| 폴링 중인데 HB 미수신 | HB를 안 쓰고 있거나 **잘못된 주소**에 씀 — HR 430000(IR 미러)에 FC16으로 쓰는지, 값이 매 초 변하는지 확인 |
| DI/IR 모니터링 값이 안 바뀜 | 미러 영역 규칙 위반 — FC16이 DI대(41만)와 IR대(43만)를 **한 요청에 섞으면 무시**됨. Hex 모니터로 도착 여부 확인 |
| 물리값이 10배/100배 이상함 | 스케일 착오 — §2.5·2.6 표 참조 (링크① 온도×10, 예측×100. 링크③과 다름) |
| 음수가 큰 양수로 보임 | INT16 2의 보수 미처리 — 예: −50.00 kW는 0xEC78 |
| Run 시작 거부 | 부하·기상 데이터 미로드 — 데이터 메뉴에서 CSV 업로드 |
| 트리거를 켰는데 되돌아감 | Run 진행 중 엔진이 덮어씀 — 수동 강제는 P0에서 (§2.4 주의) |
| '운전 시작' 토글을 켰는데 가상시계가 안 움직임 | 정상 — 토글은 ①Coil 비트만 세트하는 수동 오버라이드이며 시퀀스 엔진·가상시계를 거치지 않음. **가상시계가 도는 정상 Run은 Home의 ▶ Run 시작**(P2 초기화→P3 개시 전체 절차) 사용 |
