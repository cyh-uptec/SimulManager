# 배포 — 다른 PC 복사 대상 정리

> 다른 PC로 배포할 때 **복사할 항목만** 정리한 문서.
> 설치 절차·방화벽·IP·업데이트 방법 등 전체 가이드는 [DEPLOYMENT.md](DEPLOYMENT.md) 참조.
> 전체 폴더 복사는 불필요 — 아래 필수 목록은 약 6 MB
> (.venv 176 MB, SimulManager(WPF) 367 MB, frontend 개발 파일 81 MB는 전부 제외).

## 1. 복사 대상 (필수)

```
C:\SimulManager\                     ← 대상 PC에 이 구조로
├── install.bat                      # 최초 1회 실행 (venv 생성 + 의존성 설치)
├── run.bat                          # 기동 (서버 + 브라우저 자동 열기)
├── backend\
│   ├── app\                         # Python 소스 전체
│   ├── config\                      # default.yaml · production.yaml · user_settings.yaml*
│   └── pyproject.toml               # install.bat이 의존성 설치에 사용
├── frontend\
│   └── dist\                        # npm run build 산출물만 (src·node_modules 불필요)
├── data\
│   └── uploads\                     # 업로드했던 시나리오 CSV (있다면)
├── Load_2510.csv                    # 시나리오 원본 CSV
└── Weather_2510.csv
```

**\* `user_settings.yaml` 주의** — UI(⚙ 설정→네트워크)로 저장된 이 파일은
default.yaml·production.yaml보다 **우선** 적용된다.

| 배포 목적 | 처리 |
|---|---|
| 시험 배포 (EMS/RTDS 단독 연동 시험) | **포함** — per_link_port ①7000/③5021 그대로 사용 |
| 운영 배포 (single_port 502) | **제외** — 그리고 run.bat의 `rem set SIMUL_CONFIG=config\production.yaml` 주석 해제 |

`data\`의 나머지(historian.db, events.json, persisted_soc.json)는 **런타임 상태 파일**이라
새 PC에서 자동 생성된다. 개발 PC의 Run 이력을 가져갈 때만 `historian.db`를 포함할 것.

## 2. 선택 (필요 시)

| 항목 | 포함하는 경우 |
|---|---|
| `emulators\` + `run_emulators.bat` | 실장비 없이 현장에서 자체 점검할 때 |
| `assets\` + `apply_logo.bat` | 로고·아이콘·바탕화면 바로가기 적용 |
| `docs\` + 설계 문서(xlsx/docx) | 현장에서 참고 문서가 필요할 때 |

## 3. 제외 (복사 금지·불필요)

| 항목 | 이유 |
|---|---|
| `.venv\` | 대상 PC에서 install.bat이 새로 생성 (다른 PC 경로로는 동작 안 함) |
| `frontend\`의 `dist` 외 전부 | `node_modules`·`src`·`public`·package.json 등 — 빌드는 개발 PC에서만 |
| `SimulManager\` | WPF 포팅판 (보류 중, 367 MB) |
| `backend\tests\`, `conftest.py` | 개발용 테스트 |
| `__pycache__`, `.pytest_cache`, `simul_manager.egg-info` | 캐시·빌드 부산물 |
| `.claude\`, `이미지\`, `.gitignore` | 개발 환경 전용 |

## 4. 업데이트 — 수정 후 덮어쓸 항목

절차: 배포 PC run.bat 창 닫기 → 아래 항목 덮어쓰기 → run.bat 재실행 → 브라우저 새로고침(F5).

| 구분 | 항목 |
|---|---|
| **기본 (항상)** | `backend\app\` + `frontend\dist\` (개발 PC에서 `npm run build` 후) |
| 의존성 변경 시 | `backend\pyproject.toml` 복사 + **install.bat 재실행** |
| 설정 스키마 변경 시 | `backend\config\default.yaml` |
| bat 수정 시 | `install.bat` / `run.bat` |
| **덮어쓰기 금지** | `data\` 전체(Run 이력·업로드 CSV·보존 SOC), 배포 PC의 `user_settings.yaml`(UI 저장 설정)·현장 수정된 `production.yaml` |

## 5. 복사 후 진행

1. 대상 PC: Python 3.11+ 설치 ("Add python.exe to PATH" 체크)
   — 오프라인 PC는 [DEPLOYMENT.md](DEPLOYMENT.md) §3 방식 A의 wheels 오프라인 설치 참조
2. `install.bat` 더블클릭 → `run.bat` 더블클릭
3. 고정 IP·방화벽 설정: [DEPLOYMENT.md](DEPLOYMENT.md) §4 체크리스트
   (시험 모드는 TCP **7000**(링크① EMS)·**5021**(링크③ RTDS)·8100(웹) 인바운드 허용)
4. 확인: 웹 UI `http://<매니저IP>:8100` → EMS/RTDS 시험 페이지 상단
   '실장비 접속 상태' 카드가 장비 접속 시 "● 접속됨"으로 표시됨
